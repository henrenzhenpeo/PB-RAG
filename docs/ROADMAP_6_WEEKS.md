# PB-RAG 六周执行路线

> 状态：当前正式计划
> 原十二周方案保留为知识地图，本文件覆盖其中的时间安排。
> 建议投入：每周 20～30 小时。

## 执行策略

六周版本通过减少集成数量和外围功能压缩周期，但保留以下深度：

- Agent Runtime 自主实现；
- 权限在检索和工具执行前生效；
- 异步任务具备幂等、重试和可观测状态；
- 核心链路具备 Trace；
- RAG 与 Agent 有固定评测集；
- 必须完成故障和安全实验。

## 第 1 周：工程骨架与最短 RAG 闭环

### 目标

跑通第一条纵向链路：

```text
上传 Markdown/PDF
  → 异步任务
  → 解析与分块
  → Embedding
  → pgvector 检索
  → SSE 回答
  → 引用原文
```

### 工作内容

- Go API、PostgreSQL、pgvector、Redis 和 Docker Compose；
- 迁移、配置、结构化日志、请求 ID 和基础 Trace；
- 文档、版本、Chunk、Job、Session、Message 和 Citation 模型；
- 文件上传和对象存储接口；
- 最小 Worker 和入库状态；
- 基础向量检索与流式生成；
- 最小前端或调试界面。

### 验收

- 一条命令启动环境；
- 上传接口快速返回 Job ID；
- 能查看处理阶段和失败原因；
- 回答引用绑定文档版本；
- 端到端链路拥有 Trace ID；
- CI 可执行测试和迁移检查。

## 第 2 周：Production RAG

### 工作内容

- 关键词检索、向量检索、RRF 和 Rerank；
- 文档内容 Hash、任务幂等、失败重试；
- 文档重解析与索引版本切换；
- 保存各检索阶段中间结果；
- 无证据拒答；
- 建立 50～100 条 RAG 评测集。

### 验收

- 可以查看向量、关键词、融合和重排结果；
- 重复消费不会生成重复 Chunk；
- Worker 崩溃后任务可恢复；
- 文档更新不会造成引用版本混乱；
- 输出 Recall@K、引用准确率、拒答率和延迟基线。

## 第 3 周：Agent Runtime

### 工作内容

- Agent Run/Step 状态机；
- ReAct 核心循环；
- Tool Registry 与 JSON Schema 校验；
- `search_knowledge`、`read_document`、`list_documents`、`calculator` 和一个领域工具；
- 最大迭代、重复调用检测、Deadline、单步超时、取消和有限重试；
- SSE 执行事件、轨迹持久化和回放。

### 验收

- Agent 能完成跨文档比较任务；
- 简单问题仍可走固定 RAG；
- 每轮模型调用、工具调用和 Observation 可回放；
- 用户取消会传递到模型和工具；
- 循环和超时进入明确终态；
- 错误有结构化分类。

## 第 4 周：权限、审批与可靠性

### 工作内容

- Workspace 与基础 RBAC；
- 知识库、Agent、API Key 和工具权限交集；
- 高风险工具 Approval Gate；
- 工具审计与敏感参数脱敏；
- SSRF 防护和 Prompt Injection 基础测试；
- Agent 服务重启处理策略；
- 受限执行的最小沙箱实验，可先不做多后端。

### 验收

- 跨 Workspace 越权测试全部失败；
- Agent 不能突破当前用户权限；
- 高风险工具必须等待审批；
- 审批绑定具体参数，修改参数后重新审批；
- 敏感值不进入普通日志和 Trace；
- 恶意文档不能改变确定性权限策略；
- 服务重启后任务能够恢复、补偿或明确失败。

## 第 5 周：评测、故障实验与优化

### 工作内容

- 完善 RAG 评测集；
- 建立 30～50 个 Agent 多步骤任务；
- 统计工具选择、参数正确率、任务成功率、成本和延迟；
- 完成分块、Hybrid、Rerank、工具描述或上下文预算实验；
- 完成优先级最高的故障注入。

### 必做故障

- 重复上传与重复消费；
- Parser/Worker 中途崩溃；
- Embedding 429；
- LLM 流中断；
- 用户取消；
- Tool 超时；
- Agent 重复循环；
- 服务重启；
- 跨 Workspace 越权；
- Prompt Injection；
- SSRF；
- 日志敏感信息泄漏。

### 验收

- 每项优化都有相同数据集上的前后对比；
- 可以把失败分类到检索、推理、工具、权限或基础设施；
- 输出任务成功率、引用准确率、P95 延迟和平均成本；
- 故障实验有复现、Trace、修复和回归测试。

## 第 6 周：作品化与复盘

### 工作内容

- 清理核心边界和关键测试；
- 完善 README、部署、架构和 API 文档；
- 整理 ADR、Runbook、评测和故障报告；
- 准备演示数据和演示脚本；
- 录制演示；
- 整理简历数据和面试问答。

### 最终演示

```text
创建 Workspace
  → 上传资料并查看异步状态
  → 展示幂等或失败恢复
  → 带引用的 RAG 问答
  → Agent 跨文档分析
  → 工具调用与人工审批
  → Trace 定位一次失败
  → 比较两次评测运行
  → 展示权限隔离和审计
```

### 验收

- 新环境可以按文档部署；
- 10～15 分钟能够演示完整核心闭环；
- 项目结论有测试和评测数据；
- 可以解释架构取舍、失败处理和安全边界；
- `docs/HANDOFF.md` 不存在未说明的关键阻塞。

## 六周版本优先级

```text
P0：入库、Production RAG、Agent Runtime、评测、权限、可靠性
P1：审批、审计、Trace、故障实验
P2：MCP、上下文压缩、简单沙箱
P3：Wiki、GraphRAG、多 Agent、多渠道、完整长期记忆
```

如果进度落后，依次移除 P2、减少文档格式、减少领域工具和简化前端；不得移除 P0 的评测、权限和失败处理。
