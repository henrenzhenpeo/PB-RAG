# PB-RAG 协作规则

> 本文件只记录项目开发过程中的三项协作规则。架构、范围、安全和测试原则继续以 `PROJECT_CONTEXT.md`、`AGENTS.md` 与 ADR 为准。

## 1. 注释规则

- 后端 Java 类、前端页面、Store、API 模块和重要配置应有简短的职责说明；
- Controller 端点、Service 接口与实现、Mapper 自定义方法、解析器、分块器、存储接口等显式方法，应分别说明其功能；
- Java 方法的 Javadoc 放在 Spring、MyBatis 等注解之前，确保 IDE 能正确关联；
- 简单方法只说明“做什么”，不要逐行翻译代码；
- 核心流程重点说明“为什么这样做”，包括事务边界、幂等、Workspace 作用域、状态迁移、租约、并发、安全约束、失败语义和不直观算法；
- 修改已有逻辑时同步检查相关注释，禁止保留与实现不一致的过时说明；
- 注释不得包含密钥、密码、Token、真实敏感数据或大段文档原文。

## 2. 编译规则

- 默认只关注需求理解、业务逻辑、代码结构和静态差异，不执行编译、测试、构建、启动服务或数据库迁移；
- 编译、测试和实际运行由项目发起人完成；
- 完成修改后，应明确说明本次没有执行编译或测试，并列出建议由项目发起人运行的验证项；
- 不得把“代码已修改”描述成“编译通过”“测试通过”或“运行验证完成”；
- 只有项目发起人在当前任务中明确要求执行时，才运行相应的编译、测试、构建或启动命令。

## 3. 功能与文档同步规则

- 功能、接口、状态、配置、数据结构或稳定决策发生变化时，必须在同一次任务中更新对应文档，不能留到后续补写；
- 当前完成情况、验证状态、风险和下一步更新到 `docs/HANDOFF.md`；
- 稳定目标、范围、架构或长期边界变化时更新 `docs/PROJECT_CONTEXT.md`；
- 里程碑、优先级或验收标准变化时更新 `docs/ROADMAP_6_WEEKS.md`；
- 有后果的技术选择新增或更新 `docs/adr/` 下的 ADR，并标明替代关系；
- 项目入口、运行方式或目录变化时更新根 `README.md` 和 `docs/README.md`；
- Prompt 行为变化时更新对应 Prompt 的版本、契约和评测数据集说明；
- 评测数据、模型配置或效果结论变化时更新 `evaluation/` 下的版本化资料或报告；
- 文档只保留当前有效信息。新状态覆盖旧状态，不堆积聊天记录、重复清单和已失效的修复流水；
- 如果功能尚未验证，文档必须明确写为“已实现、待编译/待测试/待实测”，不能提前标记完成。
